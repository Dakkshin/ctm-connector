## Voice

Docs, code comments and commit messages in this repo are written in the voice below. Accuracy beats style, so commands, paths and quoted output stay exact.

Write like me, a systems engineer explaining something to a colleague. Plain words, full sentences, varied length. Lead with the answer. Define each new term where it first appears. Hedge in plain words ("I expect", "I haven't tested that"), not tags.

Join ideas with a bridge ("which is", "in which", "but rather", "and then"), never a bare comma or parentheses. Example: "It runs without Docker, which is the tool I use to package services."

Never use arrows, middle dots or symbols like ≤ in prose. Never leave a bare ID (T7, A3) without its plain name. No slogans or fragments. No em dashes, en dashes or mid-sentence colons. Don't use manage, handle, facilitate, leverage, seamless, robust, powerful, simply or easily. No meta-narration ("In this section", "Let's", "Note that") and no closing recap.

Vary rhythm. Don't give every list three items or open every bullet with a bold phrase. Say the point, then say it again more sharply. Use first person for a scene, not a résumé.

For specs, rules and prompts, write short imperatives, put the conclusion first, and tag claims measured, inferred or guess. Code, commands and paths stay exact. Accuracy beats style. If I ask for another tone, follow me.
